# 吟游诗人完美轴·完全控制版 1.0

> **警告：任何第三方插件都有可能导致封号，后果自负。开别怕，怕别开。**
>
> 本插件手动启动后会实际释放技能。1.0 是版本号，不是“全局最优、零失误、免封号”的承诺。未进行本次版本的游戏内实战验收。

## 1.0 的变化

- 用联合排程替换“音调 > 九天 > 碎心”的固定排序。搜索当前和后续两个 GCD 窗口中的单插、双插、留空与等待。
- 九天按真实 CD；碎心/失血按原生可用充能数，不把“全部充满需要多久”误认为“是否可用”。
- 旅神三诗心比较音调→九天；两诗心比较九天→三层音调、等自然触发后音调→九天、必要时提前清两层。自然触发按 80% 分支，不凭空保证；九天诗心到账也不是按下瞬间。
- 贤者歌纳入每次诗心减少 7.5 秒充能的效果。比较充能溢出、下一次九天时间与增益覆盖。
- 保护团辅顺序：当前场景最终乐章→战斗之声→后半窗口猛者；旧 NGA 对照保留旧顺序。纷乱、侧风、碎心均在候选中，不能因为九天冷却中而被长期挡住。
- DoT 计算包含持续伤害、实际剩余时长、补挂/续时的 GCD 成本、预计目标可攻击时长及已知自身增益快照。未知跳伤相位按期望计算，不向上取整。
- 观察客户端执行路径，区分“接受/排队”和“客户端执行”。手动能力技/物品也占用插入预算；插件最多双插，军神满层最多单插。仍不能阻止玩家自己手动三插。
- 不为追赶旧轴主动卡 GCD；使用原生动作锁和保守的动态锁估计。高延迟仍可能导致实战偏差，不能保证固定 50ms 以内的端到端延迟。
- 50级自动使用旧技能；目标不可选/丢失/离开射程时停火，不乱选其他敌人；原目标恢复后按当前状态重算。
- 窗口 X 停止新增自动请求；已交给游戏队列的一发可能仍会执行。不会更改或清空玩家的游戏队列。

## 安装与启动

见 [安装与测试](安装与测试.md)。DLL、同名 JSON、deps.json 必须放在一起。

升级时卸载旧开发插件，再添加 **1.0 文件夹** 中的 DLL。不要同时加载两个版本，也不要继续指向保留的 0.4.2 备份文件夹。

- `/brdcontrol config`：设置与编辑器。
- `/brdcontrol start`：手动启动。先自己选中敌人并进入战斗。
- `/brdcontrol stop`：停止新增自动动作。
- `/brdcontrol reset`：放弃旧规划，以当前状态重新开始观察。
- `/brdcontrol overlay`：显示/隐藏窗口。单独隐藏不是停止。

默认推荐通用 3-3-12。2.49 标准、2.50 进阶 3-6-9、上天恢复与自定义按钮保留。实际目标时长分别是约43/43/34和43/40/37秒；切换受安全窗口和实际CD约束。自定义GCD用于预设/兜底，真实执行以游戏读到的当前CD为准。

自定义列表需关闭“1.0联合排程”；使用你编辑的条件和顺序，但仍有等级、冷却、双插和切歌保护。列表模式不是联合收益优化模式。

## 验证与伤害判断

见 [1.0自检与伤害评估](1.0自检与伤害评估.md) 与 `verification/test-results.txt`。

模型威力不能直接当作游戏 DPS。没有装备、主属性、武器伤害、暴击/直击/信念、自动攻击、队友增益和实际战斗日志，不能报一个可信的“极限DPS”。模拟也没有证明所有场景都优于旧排序。

## 范围与限制

- 当前优化范围是吟游单目标进攻循环，不是副本机制机器人或群怪 AoE 最优解。减伤、解状态、打断、药品保留手动。
- 不接 ACT，不录屏识图，不自动选陌生目标，不上传战斗数据。
- 能处理已经观察到的不可选目标；没有副本时间轴数据就不能提前知道 Boss 上天。可手填预计可攻击秒数，0表示未知。仍可选但免疫伤害的特殊状态并未完整覆盖。
- 预测窗口有限，并使用资源期末估值与平均背景伤害；不是全战斗穷举。歌曲速度未来随机变化、所有队友增益、真实服务端跳伤相位都没有完全建模。
- 进攻威力模型参考官方7.5、100级说明；低等级按特性门槛降级。国服版本或威力不同需要重新核对，实际CD/充能/层数来自客户端。
- 观察器钩子已编译验证，但尚未在本次用户游戏进程中加载、木桩或绝本验证。API或游戏补丁变化可能导致不能加载或停止。

## 构建

需要 .NET 10 和兼容 Dalamud API 15 的开发环境：

```powershell
dotnet build BardPerfectLoopControl.csproj -c Release
dotnet run --project tests/BardPerfectLoopControl.Smoke -c Release -- --simulate
```
